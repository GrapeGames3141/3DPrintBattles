## Player-facing feature contract

- **Entry:** Either seat begins or resumes an authoritative print receipt, awakening,
  deployment, settled field idle, attack/contact/return, or reduced-motion equivalent.
- **Player decision:** Use only the already-legal Plan, focus, Run Cycle, required
  choice, Skip, Back, and accessibility actions. Facing adds no combat decision.
- **Result:** For the 23 directional species, presentation selects direction from
  field ownership, never from creature identity: friendly/lower raw print, awakened
  miniature, travel, idle, attack and return use the approved rear family; rival/upper
  equivalents use the approved front family. Voltwig alone deliberately uses its
  existing named legacy artwork on either side and remains visible and playable. One
  job becomes one living unit, with
  stable identity, feet, scale, material, matched slightly elevated board-camera angle,
  and inward orientation through the complete print -> awaken -> deploy -> idle ->
  attack chain.
- **Failure:** A missing/malformed direction, pose, alpha region, creature mapping or
  compiled resource fails interim release acceptance and names the exact
  creature/seat/beat in diagnostics; there is no general release fallback. The sole
  allowed legacy mapping is the explicit `voltwig` entry. Presentation never mirrors
  a side view and calls it rear-facing, substitutes the static proof screen, reruns
  authority, stalls, drops a catalog species, or duplicates a unit. Any other fallback
  occurrence blocks the review build from being labelled complete.
- **Disabled:** Background Plan/hand/Run Cycle targets remain locked during playback;
  rival-private targets remain inaccessible. Unsupported directional art is disabled
  as an acceptance candidate rather than silently falling back in a release claim;
  Voltwig itself is not disabled. No new Guard action, targeting option, phase control
  or skip advantage is enabled.
- **Feedback:** Ground shadow, foot anchor, inward silhouette, print scan/raw boundary,
  awakening, travel, contact, HP receipt and return describe the same receipt and unit.
  Native status/accessibility copy must not describe Voltwig's approved legacy mapping
  as directional art or as an error. Any disallowed presentation fallback remains
  truthful in diagnostics; native focus, dynamic values and captions remain unobscured.
- **Progression:** Facing, animation selection and the Voltwig legacy exception are
  presentation-only.
  Identical accepted intents must produce identical deterministic integer battle
  traces, revisions, RNG outcomes and exactly-once settlement with normal, skipped,
  reduced-motion, front-resource-missing and rear-resource-missing presentation. The
  interim build adds no reward, unlock, economy, roster, save, or pacing change.
